# DOM サンプルの採取手順（お願いしたい作業）

> **2026-08-06 時点: 追加の採取は不要です。**
> チャネル 4 ファイル・チャット 2 ファイルの採取で、送信者・日時・本文・添付・コードブロックがすべて確定しました
> （`node tools/check-samples.js` で全 79 メッセージ 100%）。
>
> 次に採取が必要になるのは、**Teams の UI 更新で命中率が落ちたとき**です。そのときは以下の手順で採り直してください。
> 方針により採取対象外: システムメッセージ（出力しない）／編集済み・削除済み（最新状態が取れればよい）。

---

## ステップ 1: チャネルで採取する（1 回）

1. Teams Web（`https://teams.microsoft.com/`）で、**低機密の**チャネルを開く（仕様書 §10）
2. `F12` → **Console** タブ
3. `tools/collect-dom-samples.js` の中身を全部コピーして、コンソールに貼って Enter
4. `teams-dom-samples_<日時>.md` が自動ダウンロードされる → このフォルダ（`docs/dom-samples/`）に置く

コンソールに、種類ごとの件数と「この画面には無かった種類」が表示されます。

## ステップ 2: チャットで採取する（1 回）

同じことを、**チャット（1:1 かグループ）**を開いた状態でもう 1 回。
チャネルとチャットは DOM が別物（送信者・日時の位置も日時属性も違う）なので、両方の採取が要ります。

## ステップ 3: 「不足」と出た種類だけ埋める

ステップ 1・2 のコンソールに `不足` と出た種類があれば、それを含むメッセージがある会話を開いてもう一度実行してください。

見つからない場合は、**テスト用の低機密チャネル（自分ひとりのチームでも可）に自分で投稿を作る**のが確実で早いです。

- コードブロック（複数行） → `</>` ボタンでコードブロックを 1 つ投稿（できれば言語指定つき）

（添付は確定済み、システムメッセージ・編集済み・削除済みは方針上不要なので、再採取は要りません。
　スクリプトの表ではこれらは「—」判定になり、不足として報告されません。）

作ったら、その会話でスクリプトを実行してください。

---

## 進め方（都度の連絡は不要）

ステップごとに報告しなくて大丈夫です。**全部終わってから、まとめて 1 回**で構いません。

- ファイル名には種別と日時が自動で入ります（例: `teams-dom-samples_channel_2026-08-06-17-07-16.md`）。日時はローカル時刻（JST）で秒まで入ります（`YYYY-MM-DD-HH-mm-ss`）。**リネーム不要**で、何度実行しても上書きされません。
- ファイルの中身に「URL・種別・種類ごとの件数表・祖先要素」が入っているので、どれが何の採取だったかの説明も不要です。
- 最後に `docs/dom-samples/` に置いて「採取したので selectors.json を更新して」と伝えるだけで済みます。

**例外**: 1 回目の実行で、
- コンソールに `[collect] メッセージが見つかりません` と赤いエラーが出た
- 種類の表が全部 0 だった
- ファイルが保存されない

のいずれかが起きたときは、その時点で連絡してください。スクリプト側の問題なので、先に直す必要があります。

---

## サンプルの扱い

- 出力される .md には**実際の会話内容と氏名**が入ります。取り扱いは仕様書 §10 に従ってください。
- 迷う内容なら、テスト用チャネルで作った投稿だけを含む採取にしてください（それでセレクタ確定には十分です）。
- スクリプトは画面に表示されている DOM を読むだけで、ネットワーク送信も認証情報へのアクセスも行いません。
